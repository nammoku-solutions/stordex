# CSV移行 — 商品現在庫と入出庫履歴の照合（2026-11-03）

対象：Issue #62、Stordex Staging（https://staging.stordex.jp）。

## 目的と安全範囲

既存Stordexから出力できる「商品・現在庫」と「入出庫履歴」を突合し、移行前のデータ不整合を見つける機能です。

**この段階は照合のみです。商品・発注・在庫・入出庫履歴の更新、在庫の初期化、マイグレーション、履歴の再計上は一切行いません。**

業務用の正式な環境は **Staging（Vercel + Neon）とProduction（AWS）の2つ**。使い捨てPostgreSQLは自動テスト専用です。ユーザーの動作確認はStaging URLだけで行います。

## 管理者による操作

1. https://staging.stordex.jp にOWNERまたはADMINでログイン。
2. 「CSV エクスポート」を開き「商品・現在庫」「入出庫履歴」を両方ダウンロード。なるべく書込みのない時間帯に取得します。
3. 「CSV 取り込み」→「在庫と履歴を照合する」を開く。
4. ①商品・現在庫CSV、②入出庫履歴CSVを選択。
5. 「在庫と入出庫履歴を照合する（書き込みなし）」をクリック。
6. 件数、現在庫、履歴最終残高、開始在庫の推定結果、警告を確認。

## 検証する条件

- 商品CSVは25列、入出庫履歴CSVは13列の現行エクスポート形式。列名の重複・欠損・未知列はFAIL。
- 商品コードの重複・空欄、現在庫の負値・小数・安全な整数範囲外はFAIL。
- 入出庫履歴IDの重複、未知の商品コード、無効なUTC日時・期限・入出庫種別、不正な数量・残高、並び順違反はFAIL。
- INBOUNDは数量を加算、OUTBOUNDは数量を減算、ADJUSTMENTは符号付き数量を加算する。ADJUSTMENTの数量は調整後の在庫数ではなく、Stordexが記録した差分。
- 最初の入出庫後残高から増減を引き、推定開始在庫を計算。負の開始在庫や桁あふれはFAIL。
- 2件目以降は「移動後残高 = 直前残高 + 今回の増減」。一致しなければFAIL。
- 商品ごとの最終残高と商品CSVの現在庫が一致すること。
- 履歴がない商品の開始在庫は推定できず、PASSでも「未検証」警告になる。
- 各CSVは2MB以下・10,000行以下。OWNER/ADMINのみ利用可能。元CSVの全行をAPIレスポンスへ返さない。

## PASSが保証しないもの

**照合PASSは完全移行・完全復元PASSではありません。**

- 現行エクスポート2種類は独立したDB取得のため、同一時点の厳密なスナップショットではありません。入出庫が動いていない時間帯に取得してください。
- 元の在庫履歴が欠落している場合、推定した開始在庫は過去の真実を保証しません。
- 倉庫ごとの数量・ロット・期限・企業間発注・請求書・返品と関連伝票の整合はまだ対象外。
- 復元を実環境で有効にする前に、履歴の読み取り専用化、二重計上防止、隔離DBでの全データ復元検証を完了する必要があります。

## Staging運用

- stagingブランチを統合先とし、CI PASSとVercelビルドREADYを確認後、staging.stordex.jpへ反映する。
- Vercel内部のデプロイ成果物に固有のURLが付いても、手動UATはStagingドメインのみを使用する。
- Staging DBへの新マイグレーションや復元書込みは、その変更ごとにバックアップの独立復元検証・対象照合・明示承認が必要。
- Productionは別途承認とCodex Astra Review PASSまで変更しない。
