# Stordex CSV仕入発注復元 — 隔離CI限定のリハーサル（2026-11-03）

関連: Issue #62、前段PR #92。

## 現在実装した範囲

`src/lib/csv/purchase-order-restore-disposable.ts`は、既存の仕入発注CSV形式を完全検証した後、**使い捨てPostgreSQL専用**で発注書と明細の履歴スナップショットを復元する内部処理です。通常ユーザー向けUI/APIは提供しません。

- `APP_ENV=ci` かつ接続先が **認証情報・ホスト・ポート・データベース・許可クエリパラメーターまで一致するローカル `postgresql://stordex:stordex@localhost:5432/stordex?schema=public`** の場合のみ実行可能。
- 既存のCSV事前検証にPASSした全件を単一Serializable transactionで扱い、仕入先コード・商品コードを現在のテナントのレコードへ解決します。他テナントの同名コード・IDにはアクセスしません。
- 発注番号による重複検知。すでに存在する発注がスナップショット（明細込み）と完全一致すればスキップ、不一致なら全体をROLLBACK。異常な参照コードでも全体ROLLBACK。
- 元の発注番号、日付、状態、金額、仕入先、商品、パック情報、入荷済数を**履歴値として**復元します。通常の`applyPurchaseOrderStatus`は呼ばず、商品在庫を更新せず、在庫移動履歴も作りません。
- バッチ上限：CSV明細最大10,000行、発注書最大1,000件。事前検証がFAILなら書込み処理は実行不可。

## これはまだ「完全な移行」ではありません

- **本実装をStaging/Productionへ利用可能にしてはいけません**。過去の受入履歴と現在庫の基準点を同時復元する契約が未整備です。
- 完了済（RECEIVED）だけでなく操作可能なDRAFT/ORDEREDを復元すると、一般のワークフローの遷移と衝突する可能性があります。実環境で有効化するには「移行済み履歴」の専用フラグや読み取り専用モード、業務画面の権限と参照・送信制約も設計する必要があります。
- 既存の企業間発注リンク、帳票参照、監査ログ、Warehouse/lot、返品、初期残高・在庫台帳の復元はこのスライスの対象外です。
- 事前検証PASSは元データの構造検証であり、完全な在庫履歴・会計整合性のPASSとは異なります。

## CIの受入条件

1. Disposable PostgreSQL 16にテスト用のテナント・仕入先・商品を作成。
2. 過去のRECEIVED発注（数量20／入荷実績21／箱数2・入数10）をCSVから復元。
3. 発注番号、税率、金額、数量、荷姿、入荷実績、作成・更新日が一致すること。
4. 同一CSVの再実行でcreated=0、skipped=1。
5. 発注番号重複でも内容が異なると、上書きせず全体ROLLBACK。
6. 別テナントの商品コード混入では全体ROLLBACK。
7. 前後で現在庫・在庫移動履歴・他テナントのデータが不変。
8. `APP_ENV=staging`などガード外環境は**DB照会の前に**拒否。
